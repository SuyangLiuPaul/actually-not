# 其实不是 / Actually, Not · App 重设计提案（v1.2 起）

> 2026-11-09 · 状态：**提案，未改任何代码**。会议过程见 `MEETING.md`，图标见 `icons/` 与 `icon-sheet.png`。
> 硬约束（从 HANDOVER §6、§13 继承）：准确优先于数量；区分「证据不足」与「已被推翻」；不给医疗建议；
> **不得有只在某日期 / 解锁后才出现的功能**（Apple 5.6 教训。唯一例外：视频的「X 月 X 日上线」卡片，它一直可见）；
> Android 包不含 `urgent` / `body`；不使用暗黑模式，不制造虚假紧迫感。

---

## 0. 一页结论

**问题不在动机，在供给和结构。**
1. 每日玩法的题库只有 10 题（`src/data/play.ts`），`dailyQuestions()` 每天用掉 2 道新题，**第 5 天起只剩复习**。230 条内容里只有 10 条进入了每日循环。
2. 「今天」页塞了 7 个模块，没有主角；「玩法」页只有两个实验，撑不起一个标签。
3. 没有任何**零成本触点**（组件、带内容的通知、可转发的结论图），用户在真正需要时（家族群转来谣言、饭桌争论）想不起这个 App。
4. 图标概念对，但画法粗糙：两根等粗的线，没有层次，29pt 下红线消失，看起来像待办 App。

**回访理由（一句话）**：*每天一条，看一眼就有收获；听到可疑说法时，10 秒查到、一键转发；你改观过的事，都记在自己的改观簿里。*

**v1.2（几天工作量，只动 Web 层和少量 Capacitor 调用）**
1. 每日「你信吗？」改为从**全部条目**自动出题（不新增内容），彻底解决题库枯竭。
2. 四个标签改三个：**今天 / 资料库 / 改观簿**。
3. 改观簿 v2：「你改观过的 N 件事」、阅读覆盖、间隔回看。
4. 本机生成的**结论分享图**（1080×1350，适合朋友圈、小红书、IG），用 canvas 绘制。
5. 提醒改为**带当天内容**的通知，由用户主动开启，延后询问权限。
6. 首次启动跟随系统语言；语言开关移进设置。
7. 换上图标 A（iOS 浅色、深色、着色三版，Android 自适应和单色版）。

**v1.3+**：iOS / Android「今日一条」桌面组件、本周回顾、Spotlight / App Shortcuts、「分享到其实不是查一下」扩展。

## 2. 设计原则（每个决定都要过这五条）

1. **内容就是奖励。** 回访的理由是「又知道了一件事」，而不是保住一个数字。
2. **记录，不惩罚。** 只记累积，不设断档；不比较，不排行，不说「差一点就……」。
3. **表态，不打分。** 用户表态的是「我信 / 说不准 / 我不信」，系统回应的是「证据怎么说」。`limited` 和 `debated` 永远不显示成「答对 / 答错」。
4. **零成本触点优先。** 组件、带内容的通知、首屏的「今日一条」，用户不用付出任何东西就能得到价值。
5. **一切可见。** 230 条（Android 194 条）随时可查，没有锁、开关或日期门槛（视频上线卡片除外）。

## 4. 核心循环与长期价值

### 4.1 每日「你信吗？」：从全部条目自动出题（v1.2 的核心改动）

**形式**（任何条目都适用，不需要手写题目）：

```
[板块 · 小插画]
「你以为」
  吃完饭马上洗澡，会伤胃。
你怎么看？
  ( 我一直这么以为 )  ( 说不准 )  ( 我不信 )
  把握：猜的 · 有点把握 · 很确定（可选，沿用现有 certainty）
          ↓ 点任一项（或「直接看答案」）
红笔划过这句话（Strike 动画）
「其实」 一句话 truth
[置信度标签] 出处明确 / 研究有限 / 尚有争议   [读解释和出处 ↗]  [分享结论图]
回应文案（按表态 × 置信度给出，诚实且不计分）
```

**回应文案矩阵**（示例，中文版；英文版同理）

| 表态 \ 置信度 | strong 出处明确 | limited 研究有限 | debated 尚有争议 |
|---|---|---|---|
| 我一直这么以为 | 「改观 +1，已记进改观簿。」 | 「现有证据撑不起这个说法，不过也不等于证明它是假的。」 | 「这条没有定论。看看两边各怎么说。」 |
| 说不准 | 「现在有出处可以帮你判断了。」 | 「你的谨慎是对的：证据确实有限。」 | 「说不准，正是这条的现状。」 |
| 我不信 | 「你的直觉和证据一致。」 | 「你的直觉和现有证据方向一致。」 | 「研究者自己也还没吵完。」 |

- **「改观」的定义**：用户表态「我一直这么以为」或「说不准」，随后读到了结论。只有这类记录计入「你改观过的 N 件事」。
- **选题规则**（按日期确定，同一天重开得到同一组）：
  - 候选池 = 当前平台的全部条目，`urgent` 除外（沿用现有规则：急救内容不进随机或游戏，但在板块里随时可读）。
  - 每天 3 条：2 条**从没表过态**的条目（尽量来自不同板块，优先挑没读过的），加 1 条**到期回看**的条目；没有到期的就补 1 条新的。
  - 第 1 条就是「今日一条」，后续组件和通知用的也是同一条，保证各处一致。
- **现有 10 道手写选择题**保留为「挑战题」：按日期轮换，偶尔替换第 3 条出现（它们的题型更有趣），不再是唯一的题库。
- **工作量**：主要是改 `journal.ts`。注意 `loadJournal()` 目前会**丢掉不在 `PLAY_QUESTIONS` 里的记录**，必须改为按全部条目 id 校验。Android 构建下被排除的 id 要**保留但不显示**，不能删掉，否则用户换平台导入时会丢数据。记录里加一个 `kind: 'belief' | 'quiz'` 字段，旧的 v1 记录按 `quiz` 读取，向后兼容。

### 4.2 间隔回看（检索练习）

- 只回看「改观了」的条目，固定间隔 **2 天 → 7 天 → 21 天**，然后毕业。研究显示扩展间隔在长期上并不比固定间隔好，所以用最简单的规则。
- 回看形式反过来问：「『吃完饭马上洗澡伤胃』，其实是怎样？」→ 用户先在心里回忆 → 点开结论 → 自评「记得 / 有点忘了」。选「有点忘了」就重排到 7 天后。
- 不计分，不显示「复习率」。改观簿里有一行「待回看 2 条」，点进去就能做。

### 4.3 改观簿：长期价值的载体

- **总览卡**（衬线大字）：「你改观过 **27** 件事」，下面一行小字：「读过 64/230 · 收藏 9」。
- **板块覆盖条**：沿用现有 `app-world-meter` 的视觉，11 条细条，只陈述「读过多少」，不设目标、不设奖励。
- **记录列表**：每条显示当时的表态和把握程度（沿用现有的「当时的直觉」），可以筛选「改观了 / 本来就不信 / 说不准」。
- **导出**：保留现有的 JSON 导出（没有账号，这是用户唯一的备份手段）。

### 4.4 本周回顾（v1.3，本机生成）

周日（或用户第一次打开新一周时）在今天页顶部出现一张卡片：「这周你改观了 3 件事：A、B、C。」只陈述事实，不说「别让纪录中断」。可以生成一张分享图。不做服务器推送。

### 4.5 结论分享图（v1.2）

- **为什么在本机生成**：OG 图有 29 MB，构建时被 `scripts/mobile/build.mjs` 删除了；插画已经在包里（4.4 MB）。
- **规格**：1080×1350（4:5，朋友圈、小红书、IG 都合适），纸色底，背景是条目插画，旧说法用衬线字体并被红笔划掉，下面是 truth、置信度标签，页脚写「其实不是 · 每条附出处 · actually-not.com/{id}」。深色模式也输出浅色图，保证在任何平台都好看。
- **实现**：`<canvas>` 绘制后 `toBlob`，用 Filesystem 写入缓存目录，再用 `Share.share({ files })` 分享（导出改观簿已经用过同样的路径）。中文字体用系统的苹方或 Noto，并做自动换行。
- **诚实要求**：`limited` 和 `debated` 条目的分享图必须印出置信度标签，不能被截成「谣言已粉碎」式的标题。

### 4.6 带内容的提醒（v1.2）

- 文案：「『吃完饭马上洗澡伤胃』，其实呢？」，内容就是当天的「今日一条」。锁屏上就能看到价值。
- 用本机通知预排未来 7 天（每条内容不同），每次打开 App 时重排。不需要服务器，不收集数据。
- **询问时机**：用户第 3 天完成「今日一条」后，在改观簿里轻轻出现一行「想每天在锁屏上看到一条吗？」，附一个开启按钮。首次启动时不申请权限；用户拒绝后不再主动询问（设置里仍可手动开启）。
- 禁止使用的措辞：「你的改观簿在等你」「别错过」「X 天没来了」。

### 4.7 「今日一条」桌面组件（v1.3，需要原生代码）

- iOS：WidgetKit 小号和中号。小号是「你以为」那句加红笔划线，点开进入当天卡片；中号加上 truth 的前 40 字。
- Android：Jetpack Glance，2×2 和 4×2。
- **数据**：App 每次打开时把未来 7 天的「今日一条」写进共享存储（iOS 用 App Group UserDefaults，Android 用 SharedPreferences），组件每天按本地日期取用。不需要网络。
- 组件内容就是当天的第 1 条，所有条目在 App 里本来就可读，所以不涉及 5.6。

## 5. 视觉系统（与网站 `src/index.css` 的设计令牌一致）

### 5.1 颜色角色（沿用现有变量，只给出用法约定）

| 令牌 | 浅色 / 深色 | 角色 |
|---|---|---|
| `--paper` / `--paper-raised` | #f7f4ee / #fffdf9 · #14130f / #1e1c18 | 底色和卡片 |
| `--ink` / `--ink-soft` / `--ink-faint` | #1c1a17 … · #f0ebe1 … | 正文三级 |
| `--pen` / `--pen-soft` | #c13024 · #f0655a | **只用于「纠正」时刻**：红笔划线、「其实」标签、改观数字。主按钮改用墨色，让红色保持稀缺、有含义 |
| `--amber` / `--amber-soft` | | 置信度「研究有限」 |
| `--slate` / `--slate-soft` | | 置信度「尚有争议」，以及信息性卡片（如回看） |
| `--rule` / `--rule-strong` | | 分隔线和描边 |

对比度要求维持现状：正文 ≥ 4.5:1，大字 ≥ 3:1。新增的组合（例如 pen-soft 底上的 pen 字）需要逐一验算。

### 5.2 字体与字号

- **衬线**（`--font-serif`，Iowan / 宋体）：只用于「内容的声音」，即那句说法、truth 大字、改观数字和页面标题。
- **无衬线**（`--font-sans`，系统 / 苹方）：用于所有界面元素。

| 级别 | 字号/行高 | 字体 | 用途 |
|---|---|---|---|
| Display | 34/1.2 · 600 | 衬线 | 今日一条的说法、改观数字 |
| Title | 26/1.3 · 600 | 衬线 | 页面标题 |
| Headline | 20/1.45 · 500 | 衬线 | 卡片标题、列表里的说法 |
| Body | 16/1.7 | 无衬线 | 正文 |
| Callout | 14/1.6 | 无衬线 | 按钮、说明文字 |
| Caption | 12/1.5 | 无衬线 | 元信息 |
| Overline | 11/1.4 · 字距 .08em | 无衬线，`--pen` | 「你以为」「其实」等标签 |

中文正文行高 1.7 到 1.8，英文 1.6。单段中文每行不超过 32 个字左右（`max-width: 34em`）。

### 5.3 间距、圆角与层级

- 4pt 基准：4 · 8 · 12 · 16 · 24 · 32 · 48 · 64。手机边距 20（最小 16），平板 32。
- 圆角：标签和小按钮 8 · 卡片 14 · 主卡片 22 · 胶囊按钮 999。
- 层级只用现有的 `--shadow`（卡片）和 `--shadow-lift`（sheet、主卡片），不新增。

### 5.4 动效

- **标志性动效**：揭晓时，红笔从左到右划过那句说法（复用 `Strike` 组件），380ms，`cubic-bezier(.2,.8,.2,1)`；truth 随后上浮 8px 并淡入，220ms；同时触发轻触感反馈（`tapFeedback`，已有）。
- 详情 sheet 用弹簧动画（阻尼约 0.85），可以下拉关闭；标签切换用 160ms 交叉淡入淡出。
- `prefers-reduced-motion: reduce` 时：划线直接出现，没有位移，只保留不超过 100ms 的淡入。
- 不做彩带、不做「+1」飞字、不做摇晃。

### 5.5 空状态（每个都要给出下一步）

### 5.6 首次使用引导

- **不做轮播引导页。** 首次启动直接进入今日一条，只加一行提示：「先表个态，再看出处」（只出现一次）。
- 完成第一条后，在卡片下方出现一行说明：「每条都附出处。所有 230 条随时可查，没有任何需要解锁的内容。」
- 通知权限按 §4.6 延后询问。

### 5.7 双语

- **首次启动**：读取 `navigator.language`，`zh*` 进中文，其他进英文；用户手动选择后记住（沿用现有的 `app-locale`）。
- 语言开关从页头移到设置，同时在资料库右上角保留一个小的「中 / EN」开关，方便看中英对照。
- App 名称已经本地化：iOS `InfoPlist.strings`（en、zh-Hans），Android `values/`、`values-zh/` 的 `app_name`。商店名称建议「其实不是 · Actually, Not」。
- 分享图和通知的语言跟随当前的 App 语言。

### 5.8 无障碍

- 所有可点区域 ≥ 44×44pt（现有已满足，新组件要保持）。
- **动态字体**：iOS 的 WKWebView 不会自动跟随系统字号。建议在原生壳里设置 `html { font: -apple-system-body }`，并把字号改用 rem 推导，让现有的「放大文字」开关变成默认跟随系统、可以手动覆盖。Android WebView 的 `textZoom` 默认跟随系统字号，需要真机核实 Capacitor 是否覆盖了这个设置。
- 红笔划线不能只靠颜色表达：被划掉的说法要给屏幕阅读器加前缀（「你以为：」「其实：」），划线本身设为 `aria-hidden`。
- 揭晓结果用 `aria-live="polite"` 播报；VoiceOver 和 TalkBack 在真机上完整走一遍「今天 → 揭晓 → 详情 → 分享」（HANDOVER 里这一项一直没做）。
- 颜色之外，置信度标签还要有文字。深色模式下所有组合都要重新验算对比度。

## 6. 图标

**推荐：A「划掉」精修版**，文件 `icons/a-strike.svg`（预览：`icons/a-strike-1024.png`，对比图：`icon-sheet.png`）。

| 文件 | 用途 |
|---|---|
| `icons/a-strike.svg` / `-1024.png` | iOS 主图标，浅色外观（铺满的正方形，由系统加圆角） |
| `icons/a-strike-dark.svg` / `-1024.png` | iOS 18+ 深色外观（墨色底、纸色对勾、亮红笔） |
| `icons/a-strike-monochrome.svg` / `-1024.png` | Android 13+ 主题图标层，也是 iOS 着色外观的基础（红笔与对勾之间留出间隙，着色后仍然能分开看清） |
| `icons/a-strike-android-foreground.svg` / `-background.svg` | Android 自适应图标：前景缩到 0.77 倍，落在 66dp 安全圆内 |
| `icons/a-strike-variants-check.png` | 自查图：Android 圆形遮罩与安全圆（绿色虚线）、单色版着色效果、深色版 |
| `icons/b-turn.*`、`icons/c-noteq.*` | 备选 B「翻过来」、C「不等于」 |

**为什么选 A**
- 概念就是 App 名字本身：你以为对的（✓），被红笔划掉。网站 favicon、OG 图、页面里的 `Strike` 划线动画说的是同一种视觉语言，品牌累积最快。
- 相比现有图标的改进：分成纸、墨、红笔三层并加投影，有了 Liquid Glass 时代需要的纵深；红笔改成左重右轻的落笔笔触，不再是机械直线；字形放大约 10%，红笔加粗，60px 下仍然清楚；纸纹只在大尺寸下可见。
- 天然适合分层：背景（纸）、前景（墨和红笔）可以直接放进 Icon Composer 和 Android 自适应图标。

**风险**
- 浅色壁纸上，纸色图标的边缘对比较弱（Notes、Photos 等白色图标也有同样的问题）。如果 Paul 在意，可以把底色压暗到 #efe8db。
- 红笔是带锥度的弧形笔触，单独看可能让人联想到某运动品牌的标志。已经把尾端改成圆钝收笔、接近水平，而且永远和对勾一起使用。**提交商店前请 Paul 亲自看一眼。**
- 29px（设置页、Spotlight）下红笔只剩约 2px 高，可以认出来但很细；60pt 的桌面尺寸没有问题。

**B 什么时候更好**：如果 Paul 想要「看起来完全换了一个 App」的效果，B 在小尺寸下最醒目。建议同时把卡面上的对勾也改成被划掉的，保住品牌语义。

**落地**（v1.2，约半天）：iOS 用 Icon Composer 导入 A 的分层（背景是纸，前景是对勾和红笔），导出深色版和着色版，替换 `AppIcon.appiconset`；Android 用 `mipmap-anydpi-v26/ic_launcher.xml`（foreground、background、monochrome）；网站 `assets/icon.svg` 可以用同一个母版重新运行 `scripts/generate-icons.mjs`。小尺寸 favicon 需要单独做一版「无阴影、无纸纹、线更粗」的版本，因为 16px 下阴影会糊掉。
